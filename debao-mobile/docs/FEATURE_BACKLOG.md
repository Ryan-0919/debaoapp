# 得宝 APP 功能拆分清单

更新时间：2026-09-02

当前前端已经完成 28 个页面的 React Native 原型复刻。本文拆分的是从“原型可操作”到“可正式上线”还需要完成的真实产品能力。默认 `environment.useMocks=true` 仅用于原型 fixture；在 `DEBAO_USE_MOCKS=false` 下，登录、题库、课程、学习、订单、论坛、通知和部分批改数据已走本地 API。支付、AI 生产 Provider、媒体、直播、下载、推送和附件上传仍不能作为生产能力。

移动端实施计划和 Goal 执行顺序以 [BUSINESS_DEVELOPMENT_PLAN.md](BUSINESS_DEVELOPMENT_PLAN.md) 为准；独立后台已于 2026-08-31 单独立项，详细范围和后台 Goal 提示词见 [ADMIN_CONSOLE_DESIGN.md](ADMIN_CONSOLE_DESIGN.md)。

## 优先级定义

| 优先级 | 含义 |
|---|---|
| P0 | 没有它无法登录、学习、答题或购买，必须先做 |
| P1 | 主流程可用后必须补齐的核心体验 |
| P2 | 运营、增长、体验和长期维护能力 |

## 一、基础工程与服务层

| 编号 | 功能 | 具体工作 | 验收条件 |
|---|---|---|---|
| BASE-01 | API 网关 | 环境配置、HTTPS、超时、重试、请求 ID、统一 `ApiEnvelope`/`ApiFailure` | 所有请求都能区分成功、业务错误、鉴权失效和网络错误 |
| BASE-02 | 登录态 | Access Token、Refresh Token、安全存储、自动刷新、失效回登录 | 重启 App 后登录态正确恢复；Token 失效不会死循环 |
| BASE-03 | 全局状态 | 用户、课程权益、草稿、收藏、错题、未读数的缓存和失效策略 | 登录/退出/切换账号后本地数据不串号 |
| BASE-04 | 错误与加载 | 页面 loading、空态、重试、离线提示、重复提交保护 | 每个网络页面都有 loading/error/empty/success 四类状态 |
| BASE-05 | 监控 | 崩溃、接口耗时、关键点击、支付和播放错误埋点 | 能按用户、设备、版本查询关键失败链路 |
| BASE-06 | 后台管理 | 已完成详细设计；用户、内容、课程、交易、社区、运营、AI、数据、RBAC 和审计按 ADMIN-00 至 ADMIN-09 实施 | 运营无需改代码即可维护主要业务，且所有高风险操作可审计 |

## 二、账号与用户

页面：用户资料、设置、我的。

登录基础闭环已于 2026-08-31 完成：真实模式登录门禁、短信验证码、运营商一键登录、微信首次强制绑定手机号、会话恢复和退出登录均已有本地实现与测试。下表保留正式供应商联调和账号安全增强项。

| 编号 | 功能 | 具体工作 | 验收条件 |
|---|---|---|---|
| AUTH-01 | 手机号登录 | 手机号校验、短信验证码、验证码倒计时、频控、图形验证 | 正确验证码登录；错误、过期、频繁请求有明确提示 |
| AUTH-01A | 手机号一键登录 | 三端号码认证 SDK、运营商 token 服务端核验、短信回退 | 本地流程已通过；正式 SDK 失败不会伪造手机号且可回退短信 |
| AUTH-01B | 微信登录与绑定 | 微信 OAuth、首次强制绑定手机号、再次直接登录、解绑审计 | 本地流程已通过；真实 AppID/签名/回调需三端真机验收 |
| AUTH-02 | 用户资料 | 昵称、备考阶段、考试年份、头像上传和修改 | 修改后服务端保存，重新登录和多设备都一致 |
| AUTH-03 | 手机安全 | 脱敏手机号、换绑手机号、设备列表、异地登录提醒 | 手机号不被客户端伪造；换绑需二次验证 |
| AUTH-04 | 账号操作 | 已实现退出、注销 7 天冷静期/撤销/到期执行、隐私协议和用户协议入口 | 正式法务主体信息与客服联系资料待提供 |

## 三、首页与内容运营

页面：首页。

| 编号 | 功能 | 具体工作 | 验收条件 |
|---|---|---|---|
| HOME-01 | 主客观题模式 | 保存用户上次模式、模式对应入口和推荐内容 | 重启后模式保持；切换不误跳页面 |
| HOME-02 | Banner | Banner 配置、图片/CDN、跳转类型、开始/结束时间、曝光点击埋点 | 后台可上下架；过期 Banner 不显示 |
| HOME-03 | 考试信息 | 考试日期、倒计时、地区/考试版本配置 | 服务端时间计算一致，跨时区不出现负数 |
| HOME-04 | 公告 | 公告列表、轮播、关闭、已读、详情跳转 | 关闭后按策略隐藏；新公告可产生未读数 |
| HOME-05 | 热门与社区 | 热门课程排序、社区热帖摘要和入口 | 内容可分页/下拉刷新，异常时有空态 |

## 四、题库与答题

页面：题库、主观题选择、主观题答题、客观题答题、客观题报告。

| 编号 | 功能 | 具体工作 | 验收条件 |
|---|---|---|---|
| Q-01 | 题库内容 | 科目、章节、年份、卷别、难度、题量和题目版本 | 筛选结果与后台题目数一致 |
| Q-02 | 客观题组卷 | 章节练习、历年真题、随机练习、考试模式和组卷规则 | 服务端返回固定题单和 `submissionId` |
| Q-03 | 客观题作答 | 单选、多选（如有）、上下题、答题卡、计时、自动保存 | 断网/退出后可恢复；不会丢答案或重复提交 |
| Q-04 | 客观题判分 | 服务端判分、得分、正确答案、解析和科目统计 | 客户端不能自行决定分数；报告可重复读取 |
| Q-05 | 主观题作答 | 五道题、小问、字数统计、草稿、题目切换、法条入口 | 草稿跨设备恢复，提交前可确认题目完整性 |
| Q-06 | 题目版本 | 题目版本号、答案版本、下架和纠错 | 历史报告仍按当时版本展示 |
| Q-07 | 答题记录 | 分页、按时间/科目筛选、记录详情和报告跳转 | 新提交记录在多设备可见，分页不重复 |

## 推荐实施顺序

1. P0 基础层：API 网关、登录、用户、题库、答题提交、课程目录、订单模型。
2. P0 交易闭环：Android/iOS/Harmony 支付、订单回调、课程权益。
3. P1 学习闭环：草稿同步、报告、错题、收藏、学习计划、答题记录。
4. P1 内容能力：视频、音频、直播、讲义、下载和推送。
5. P1 AI 与批改：AI 网关、审核、额度、文件上传、人工批改流程。
6. P2 运营能力：法条版本、论坛、公告后台、优惠券、埋点和数据报表。
7. 上线专项：三端原生构建、真机矩阵、性能、安全、隐私和应用商店审核。
