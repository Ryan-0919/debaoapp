# 得宝 APP 业务开发总计划

更新时间：2026-08-31

## 1. 目标与边界

本计划用于把现有的 28 页 React Native 原型和本地 API 骨架推进为可连接真实数据、可持续保存、可测试、可发布的业务系统。

按业务模块查看当前“已有 / 未完成 / Goal 顺序”时，以 [BUSINESS_MODULE_STATUS.md](BUSINESS_MODULE_STATUS.md) 为入口；本文继续负责详细工作包、技术边界和验收标准。

本计划原本明确不开发：

- 独立运营后台 Web 页面。
- 后台角色、菜单、工作台和可视化报表。
- 对现有 `/v1/admin/*` 占位接口做功能扩建。

2026-08-31 用户已单独批准建设后台管理。后台不并入本移动端工作包，独立使用 `debao-admin` 工程并以 [ADMIN_CONSOLE_DESIGN.md](ADMIN_CONSOLE_DESIGN.md) 为唯一设计和 Goal 基线；本文件后续关于“后台暂缓”的文字只约束原移动端 Goal，不能用于阻止独立后台 Goal。

本轮仍需开发：移动端全部用户业务、服务端业务规则、数据库迁移、内容导入脚本、供应商适配器、三端原生桥接、自动化测试和配套文档。没有后台页面时，题库、课程、法条和商品等初始化数据通过受版本控制的 JSON/CSV 模板及命令行导入脚本维护。

## 2. 当前基线

已经完成：

- Figma Make 的 28 个页面已完成 React Native 代码迁移和 Android 回归；逐页视觉 1:1 是否完成，以 [PAGE_PARITY_MATRIX.md](PAGE_PARITY_MATRIX.md) 中的源码、原型截图、交互和对照截图证据为准，不能仅以页面可运行或共享 Bundle 通过代替验收。
- Android、iOS、HarmonyOS 共享 JS 业务代码和工程骨架已经建立，三端 production bundle 通过。
- Access Token、Refresh Token、短信登录、本地一键登录、微信首次绑定手机号、再次微信登录和退出登录已有本地闭环。
- 服务端已有 PostgreSQL/Redis 接口、`001` 至 `042` 迁移、OpenAPI、统一响应、错误码和外部 Provider 适配器边界；`032` 覆盖高金额退款双人复核与拒绝原因审计，`033` 持久化后台系统设置与退款复核阈值，`035` 保证待处理举报按帖子/用户并发幂等，`042` 持久化公告生命周期和触达字段。
- 题目、课程、订单、学习、通知、法条、论坛、批改、AI 和媒体已有部分基础接口或本地实现。
- 当前验收基线为移动端 `pnpm check` 的 36 suites / 73 tests、Flutter `flutter test --no-pub` 的 98 tests，以及服务端 `npm run check` 的 54 tests；数字以本轮命令输出为准。

尚未达到生产标准的关键事实：

- 移动端默认 `DEBAO_USE_MOCKS=true`。
- 服务端未配置数据库时允许内存降级；Docker Compose 已在本机完成 PostgreSQL/Redis 健康、迁移重复执行、跨重启恢复和管理员登录验证。
- 页面正常态仍有原型数据；部分真实接口失败后缺少严格的 loading/error/empty/retry 状态。
- 支付、短信、微信、一键登录、推送、AI、媒体、直播和批改没有完成真实供应商联调。
- iOS 尚未完成 Xcode 原生构建，HarmonyOS 尚未完成 HAP 构建和真机启动。

## 3. 实施原则

1. 保持现有 28 页正常态的 1:1 视觉，不借业务开发重新设计页面。
2. 新增业务状态只补 loading、empty、error、offline、disabled、permission 和 retry，不改变原型正常态结构。
3. 生产模式不得静默回退到 Mock；Provider 未配置时返回明确错误或禁用能力。
4. PostgreSQL 是生产业务事实来源，Redis 只用于缓存、限流、一次性票据和短期状态。
5. 金额、分数、权益、库存、批改次数和账号身份只能由服务端判定。
6. 每个写接口必须考虑鉴权、用户隔离、幂等、并发、审计和重放。
7. 所有 Provider 私钥只存在服务端环境变量或密钥管理系统，客户端只持有公开配置和一次性凭证。
8. 每个工作包同时交付代码、迁移、OpenAPI、测试、环境变量示例和进度文档。
9. 外部材料缺失时完成适配器、沙箱和失败状态，然后继续下一工作包，不用假数据宣称真实联调成功。

## 4. 工作包

### WP-00 生产运行基础

范围：

- 启动 PostgreSQL、Redis 和 API 容器，验证 `001` 至 `042` 迁移可重复执行，并覆盖退款双人复核、系统设置、举报幂等和公告生命周期字段。
- 生产环境禁止数据库静默降级为内存；启动时校验数据库、Redis和关键密钥。
- 建立开发、测试、预发布、生产四套配置边界，不提交任何真实密钥。
- 补充分页游标、统一时间格式、幂等键、结构化日志、敏感字段脱敏、限流和健康检查。
- 增加数据库备份/恢复说明、迁移回滚策略和 CI 检查命令。

验收：

- API、PostgreSQL、Redis 重启后用户、会话、答题、订单和学习数据不丢失。
- 生产配置缺少数据库或短密钥时启动失败，不进入伪生产状态。
- `docker compose config`、迁移测试、服务端测试和 OpenAPI 解析全部通过。

### WP-01 账号与用户安全

状态：业务闭环已实现；真实供应商、头像文件存储和三端真机联调受外部材料阻塞。

范围：

- 正式化短信验证码：用途、过期、单次消费、手机号/IP/设备频控和风控错误码。
- 完善微信绑定、解绑限制、身份冲突、手机号换绑和二次验证。
- 完成账号注销申请、7 天冷静期、撤销注销、执行状态和数据处理记录。
- 完成登录设备列表、移除设备、会话吊销、异地登录事件和安全通知。
- 增加头像选择、压缩、上传、更新和旧文件清理。
- 用户协议、隐私政策、第三方 SDK 清单和账号注销说明提供可打开的正式页面或远程文档入口。
- Android/iOS/HarmonyOS 保持统一 `DebaoAuthProvider` 契约，接入真实 SDK 时不改页面业务逻辑。

验收：

- 两个账号、两个设备之间的数据和会话完全隔离。
- 验证码不能重放，换绑必须完成原号码或等效二次认证。
- 移除设备后对应 Refresh Token 立即失效。
- 注销全流程和撤销流程有服务端测试与审计记录。

本轮交付记录：

- 验证码已实现 5 分钟过期、单次消费、5 次失败上限及手机号/IP/设备频控。
- 微信登录首次绑定手机号、登录后绑定/解绑、手机号双验证码换绑、Refresh Token 轮换已实现。
- 登录自动登记设备，设备移除同步吊销会话；注销支持短信验证、7 天冷静期、撤销和到期匿名化执行。
- 新增账号安全页、用户协议、隐私政策、第三方 SDK 清单、注销说明页，原设置/资料页面只接通原有入口。
- 头像颜色和远程 URL 可持久化；图片选择 Native Module 契约已建立。对象存储上传、压缩裁剪和内容审核列入外部阻塞，不冒充完成。

### WP-02 题库与答题闭环

范围：

- 定义题库 JSON/CSV 导入模板和校验命令，支持科目、章节、年份、卷别、难度、题型、选项、答案、解析和版本。
- 支持题目启用/停用、版本冻结和历史报告引用旧版本。
- 服务端生成章节练习、历年真题、随机练习和考试模式题单，并返回 `submissionId`、题目顺序和服务端计时信息。
- 客观题支持单选、多选、答案自动保存、断线恢复、交卷幂等和服务端判分。
- 主观题支持多小问草稿、字数、跨设备恢复、提交确认和不可变提交快照。
- 完成答题报告、科目统计、题目解析、做题记录分页和筛选。
- 错题自动收录/移除、复习状态、再次作答和题目收藏/取消收藏完整闭环。

验收：

- 客户端无法提交自定义分数或正确答案覆盖服务端结果。
- 杀进程、断网和换设备后，未提交答案可以恢复。
- 同一 `submissionId` 重复交卷只生成一份报告。
- 题目更新后，历史报告仍展示提交时的题目和解析版本。

### WP-03 学习计划、报告与首页数据

范围：

- 学习计划支持创建、编辑、删除、起止日期、每日目标和提醒时间。
- 学习任务支持开始、完成、逾期、补做和重复任务。
- 统一上报答题时长、课程播放时长和任务完成事件，形成日/周/月统计。
- 学习报告生成总时长、做题量、正确率、科目趋势和薄弱项。
- 首页主客观模式持久化；考试日期、Banner、公告、热门课程和社区摘要全部走真实 API。
- 没有后台管理页面期间，首页内容使用版本化导入文件和脚本更新。

验收：

- 同一账号多设备上的计划、任务和统计最终一致。
- 周/月边界、时区和重复上报不会造成统计翻倍。
- 首页不再依赖 `src/data/mock.ts` 才能展示真实模式正常态。

- 使用 PostgreSQL 全文索引或项目现有技术栈可维护的索引完成搜索、筛选、分页和高亮摘要。
- 法条收藏与关联练习写入用户数据，支持取消收藏和跨设备同步。
- 论坛补齐发帖、详情、回复、点赞/取消、举报、作者删除、分页和用户隔离。
- 未建设后台期间，举报内容进入待处理状态；不实现运营审核页面。
- 公告已补齐草稿、定时/立即发布、到期、撤回、受众、置顶、详情深链和已读/关闭策略；后台提供筛选、预览和触达统计。

验收：

- 法条搜索结果明确展示版本和效力状态。
- 用户只能删除自己的帖子或回复；点赞和举报接口幂等。
- 论坛和公告在真实模式没有数据时显示空态，不回退到原型帖子。

论坛本轮交付记录：

### WP-05 课程、媒体与直播

范围：

- 定义课程/章节/课时/讲义导入格式，支持试看、有效期和课程权益。
- 媒体服务返回短时签名播放地址、字幕、清晰度和过期时间；客户端支持静默刷新。
- 视频实现真实播放、进度拖动、倍速、字幕、全屏、断点续播和播放进度同步。
- 音频实现真实播放、后台播放、锁屏控制、耳机事件、倍速、字幕和播放队列。
- 讲义和时间点笔记支持创建、修改、删除、同步和重新打开。
- 下载支持授权、暂停/恢复、完整性校验、账号隔离、过期清理和空间管理。
- 直播支持房间 Token、未开播/直播中/已结束、预约、人数、被踢出、回放和断线恢复。

验收：

- 无课程权益的账号无法仅靠客户端修改参数播放完整内容。
- 播放地址过期后可以刷新，退出账号后离线内容不可继续访问。
- 来电、切后台、锁屏和耳机操作在各平台符合系统行为。
- 供应商未配置时页面展示明确不可用状态，不播放演示计时冒充真实媒体。

### WP-06 商品、订单、支付与售后

范围：

- 商品支持分类、SKU、上下架、原价、活动价、库存和课程权益映射；初始化数据走导入脚本。
- 下单由服务端重新计算金额，支持幂等键、订单超时、待支付/已支付/关闭/退款状态机。
- Android 接入选定的微信/支付宝支付，iOS 数字内容使用 App Store IAP，HarmonyOS 使用选定的合规支付渠道。
- 服务端完成回调验签、交易查询、收据校验、重复通知去重和支付成功后开通权益。
- 支持恢复购买、取消未支付订单、退款申请、退款进度、权益回收和对账记录。

验收：

- 客户端伪造支付成功不能开通课程。
- 重复点击下单、重复支付回调和重复恢复购买不会产生重复订单或权益。
- 退款完成后按规则回收权益，并保留订单和审计记录。
- 三个平台分别有沙箱支付测试证据；没有凭据时只完成适配器和沙箱模拟，不标记真实支付完成。

### WP-07 主观题批改

详细业务模型、独立批改人员工作台、AI 首轮和统计口径见 [GRADING_SYSTEM_DESIGN.md](GRADING_SYSTEM_DESIGN.md)。本工作包不是简单的文件队列，必须从后台配置“支持批改题目”和采分点开始。

范围：

- 使用对象存储预签名上传，支持图片/PDF 选择、压缩、大小和类型校验、进度、取消及失败重试。
- 批改权益次数采用事务或等效原子操作预占、扣减、释放和退款回滚。
- 批改状态覆盖提交快照、AI 排队/处理中/失败、人工待领取/处理中、人工退回、主管复核、已发布、申诉和超时升级。
- AI 首轮依据题目版本的批改依据及采分点输出结构化建议；人工老师确认或修改后才生成用户报告。
- 批改人员使用独立登录和权限范围，模型配置、OpenAI key、提示词和成本数据仅限服务端及系统管理员。
- 记录每小时/每日/每人完成量、处理时长、SLA、AI/人工差异、退回率、申诉率和成本。
- 支持 Provider 回调验签、重复回调去重、分数、教师评语和批注文件。
- 结果完成后生成站内通知，推送可用时再发送系统推送。

验收：

- 同一提交并发请求只扣减一次批改权益；同一任务并发领取只允许一个批改人员成功。
- 弱网中断后可恢复上传；非法文件和超限文件在上传前后都被拦截。
- 状态完全由服务端驱动，重启 App 后可恢复。

### WP-08 AI 法律答疑

范围：

- 保存会话、标题、消息、分页、删除和重命名。
- 使用 SSE 或当前技术栈可稳定支持的流式协议，支持增量渲染、取消、重试和断线失败状态。
- 构建法条检索增强链路，回答中的法条引用必须关联本地权威法条记录。
- 支持题目上下文，但不得把正确答案、用户隐私或供应商密钥暴露到不受控日志。
- 增加日/月额度、并发限制、敏感内容审核、成本记录和 Provider 超时/降级策略。

验收：

- 重启后会话历史可恢复，删除后不可再次访问。
- 流式中断有明确恢复或重试状态，发送按钮不会重复提交。
- 每个法条引用可以打开对应来源；无法验证来源时不生成伪造引用。

### WP-09 通知与深链

范围：

- 注册、刷新和撤销 APNs、Android FCM/厂商通道、Harmony Push Token。
- 通知中心支持分页、分类、单条已读、全部已读和未读数。
- 支持订单、课程、直播、学习提醒、批改和账号安全通知模板。
- 通知点击通过类型化深链进入正确页面；无效目标安全回退。
- 设置页增加通知偏好和系统权限状态同步。

验收：

- 三端前台、后台和冷启动均能处理测试通知。
- 切换账号后旧账号 Token 解除绑定，不发生串号推送。
- 重复通知回执和重复点击不会造成重复业务操作。

- 所有自动化检查、OpenAPI 解析、迁移测试和 `git diff --check` 通过。

工作包按顺序推进；允许在缺少某个 Provider 凭据时完成其本地部分后继续，但 WP-10 发布候选不能绕过真实供应商和真机验收。

## 6. Goal 拆分

### Goal A：当前环境可完成

包含：

- WP-00 至 WP-10 中不依赖真实商户、模型、推送证书、媒体合同、macOS、DevEco 或真机的全部代码。
- 完整业务模型、数据库迁移、客户端状态、Provider 契约、HTTP 适配器、沙箱、自动化测试和文档。
- JSON/CSV 内容模板及命令行导入，不开发后台管理页面。

完成标准：本机能够完成的事项全部通过验证；每个外部阻塞项都写清缺少材料、接入位置、验收命令和预期结果。

### Goal B：资料到位后联调

入口条件：

- 短信、微信、一键登录、支付、AI、媒体/直播、对象存储和推送供应商资料。
- Android、Apple、HarmonyOS 开发者账号、正式包名和签名。
- macOS/Xcode、DevEco Studio 和三端真机。
- 合法题库、课程、法条和商品数据。

完成标准：供应商沙箱、三端真机、回调验签、失败恢复和应用商店预审全部有真实证据。

## 7. 全局完成定义

一个业务工作包只有同时满足以下条件才能标记完成：

1. 移动端正常态和异常态已实现，且没有破坏原型 1:1 正常态。
2. 服务端校验、用户隔离、幂等、并发和审计已实现。
3. 数据库迁移可重复执行，历史数据兼容。
4. OpenAPI、客户端 contract、错误码和环境变量示例同步更新。
5. 单元测试、服务端集成测试和必要的客户端交互测试通过。
6. `DEBAO_USE_MOCKS=false` 下不存在静默 Mock 回退。
7. 文档只记录实际执行结果，不把 bundle、沙箱或本地适配器写成真实平台联调。
